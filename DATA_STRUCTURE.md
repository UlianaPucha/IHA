# Структура данных IELTS Reading Trainer

Тексты и задания поставляются вместе с приложением. Аккаунты и прогресс сохраняются в браузере в `localStorage`. Сервер и внешняя база данных в проекте не используются.

## Тексты и задания

В [src/data/passages.json](src/data/passages.json) хранится массив из трёх текстов. У каждого текста пять вопросов и десять подсвеченных слов с готовым переводом.

| Поле текста | Тип | Назначение |
|---|---|---|
| `id` | Строка | Идентификатор текста, например `urban-bees` |
| `title`, `topic` | Строки | Заголовок и тема |
| `paragraphs` | Массив строк | Абзацы текста |
| `words` | Массив объектов | Подсвеченные слова. У каждой записи есть `word` (слово), `translation` (перевод) и `example` (пример) |
| `questions` | Массив объектов | Вопросы. У каждого есть `id`, `text`, `options` (четыре варианта) и `answer` (индекс правильного варианта от 0 до 3) |

Идентификаторы вопросов могут повторяться в разных текстах. Ответ пользователя определяется парой `passageId` и `questionId`.

## Аккаунты и вход

| Ключ в `localStorage` | Структура | Что хранится |
|---|---|---|
| `ielts.users` | Массив объектов `{ id, email, salt, passwordHash, createdAt, legacyHandled }` | Идентификатор аккаунта, email в нижнем регистре, соль, хэш пароля, время создания и признак того, что пользователь ответил на предложение о переносе старых данных |
| `ielts.session` | Объект `{ userId, at }` | Идентификатор текущего аккаунта и время входа. При выходе ключ удаляется |
| `ielts.authDraft` | Объект `{ email }` | Email, введённый в форму. После успешного входа или регистрации ключ удаляется |

Пароль обрабатывается в браузере. В записи аккаунта хранится хэш SHA-256 с солью. Это демо-вход, поэтому он не подтверждает личность и не ограничивает доступ к данным для того, у кого есть доступ к хранилищу браузера.

## Данные аккаунта

Ключи начинаются с `ielts.u.<userId>.`, где `userId` совпадает с `id` записи из `ielts.users`. У каждого аккаунта свой словарь, прогресс, открытый экран и сессия карточек.

| Ключ в `localStorage` | Структура | Что хранится |
|---|---|---|
| `ielts.u.<userId>.vocab` | Массив объектов `{ id, word, translation, example, passageId, status, addedAt }` | Сохранённое слово, перевод, пример, идентификатор исходного текста и время добавления. Статусы `learning` («учу») и `known` («выучено») |
| `ielts.u.<userId>.results` | Объект `{ [passageId]: { best, total, lastAt } }` | Лучший счёт, число вопросов и время последней проверки по каждому тексту |
| `ielts.u.<userId>.drafts` | Объект `{ [passageId]: { answers, checked } }` | `answers` связывает идентификатор вопроса с индексом выбранного варианта. `checked` показывает, открыт ли разбор. «Пройти ещё раз» сбрасывает ответы и разбор текущего текста |
| `ielts.u.<userId>.view` | Объект `{ screen, passageId }` | Последний экран: `list` (тексты), `reading` (чтение), `vocab` (словарь) или `cards` (карточки). `passageId` — идентификатор текста или `null` |
| `ielts.u.<userId>.cards` | Объект `{ queue, answered, known }` или `null` | `queue` содержит идентификаторы оставшихся слов из словаря. `answered` — число уже оценённых карточек, `known` — число ответов «Знаю» |

Записи дат и времени имеют тип числа и хранятся в миллисекундах с начала эпохи Unix. Слово сохраняется в нижнем регистре. Повторное добавление того же написания в словарь аккаунта не создаёт дубликат, даже если слово встречается в другом тексте.

Пример значения ключа `ielts.u.<userId>.vocab` с одной демонстрационной записью:

```json
[
  {
    "id": "beekeeping-1763290000000",
    "word": "beekeeping",
    "translation": "пчеловодство",
    "example": "Over the past two decades, beekeeping has moved from the countryside to the rooftops of major cities.",
    "passageId": "urban-bees",
    "status": "learning",
    "addedAt": 1763290000000
  }
]
```

## Сохранение и перенос

- [src/storage.js](src/storage.js) сериализует данные в JSON и проверяет их форму при чтении. Повреждённые записи отбрасываются. Если запись в `localStorage` недоступна, изменения сохраняются в памяти вкладки до перезагрузки.
- Данные сохраняются после перезагрузки при открытии приложения в том же профиле браузера с тем же протоколом, хостом и портом. Например, порты 5173 и 4173 имеют отдельные хранилища.
- Старые ключи `ielts.vocab` и `ielts.results` используются для переноса данных из версии до демо-входа. При переносе [src/auth.js](src/auth.js) записывает данные под ключами аккаунта, объединяет словарь по написанию, сохраняет лучший результат по тексту и удаляет старые ключи.
- Открытое окно перевода, незавершённый ввод перевода и перевёрнутая сторона карточки остаются временным состоянием интерфейса.
