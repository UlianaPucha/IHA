## 1. Части приложения

Одностраничное приложение без сервера: React 19 + Vite 8 + Mantine 9.7.4, всё работает в браузере.

| Часть | Файл | Что делает |
|---|---|---|
| Точка входа | `src/main.jsx` | подключает Mantine и тему, рендерит `App` |
| Оболочка | `src/App.jsx` | `App`: без входа — экран `Auth`, затем окно переноса, после входа — `Trainer` с `key={userId}`: шапка с меню и «Выйти», выбор экрана, все данные аккаунта и действия над ними |
| Вход (mock) | `src/auth.js` | регистрация, вход, выход, сессия, хэш пароля SHA-256 с солью (Web Crypto), черновик email, перенос старых данных |
| Экраны | `src/screens/` | `Auth` — вход и регистрация, `PassageList` — список текстов, `Reading` — чтение, вопросы, разбор, `Vocabulary` — словарь, `Flashcards` — карточки и итог |
| Компоненты | `src/components/` | `WordPopup` — попап слова, `BottomBar` — нижняя панель с кнопками, `TransferModal` — окно «Перенести данные в аккаунт?» |
| Хранилище | `src/storage.js` | `readJSON` / `writeJSON` / `removeKey` (без `localStorage` — в памяти), проверки формы всех ключей, хук `useLocalStorage` |
| Контент | `src/data/passages.json` | 3 текста с вопросами и подсвеченными словами |
| Оформление | `src/theme.js`, `src/index.css`, `index.html` | тема Mantine и CSS-переменные из DESIGN.md, шрифты Google Fonts |

Как части общаются:
- данные и действия лежат в `App` и передаются экранам через props;
- экраны сами ничего не сохраняют, а вызывают действия `App`: `onAddWord`, `onCheck`, `onSetStatus`, `onDelete`;
- маршрутизатора нет. Экран выбирается состоянием `screen`: `list | reading | vocab | cards`. Адрес в браузере при этом не меняется.

## 2. Сущности и поля

### Текст (Passage) — контент, только чтение
| Поле | Тип | Смысл |
|---|---|---|
| `id` | строка | `"urban-bees"`, `"salt-history"`, `"sleep-memory"` |
| `title` | строка | заголовок на английском |
| `topic` | строка | «Экология» / «История» / «Наука», задаёт цвет карточки |
| `paragraphs` | строки[] | абзацы текста |
| `words` | `{ word, translation, example }`[] | подсвеченные слова с готовым переводом |
| `questions` | `{ id, text, options, answer }`[] | вопросы: `options` — 4 варианта, `answer` — номер правильного (0–3) |

### Слово в словаре (VocabEntry) — создаёт пользователь
| Поле | Тип | Обязательно | Смысл |
|---|---|---|---|
| `id` | строка | да | `слово-время`, например `"decline-1794852924085"` |
| `word` | строка | да, не пустая | слово строчными буквами |
| `translation` | строка | да, не пустая | готовый перевод или введённый пользователем |
| `example` | строка | да | пример из контента или предложение из текста |
| `passageId` | строка | да | из какого текста добавлено |
| `status` | `"learning"` \| `"known"` | да | «учу» / «выучено» |
| `addedAt` | число | да | время добавления, мс |

### Результат текста (Result)
| Поле | Тип | Смысл |
|---|---|---|
| ключ | строка | `id` текста |
| `best` | число | лучший счёт, `0 ≤ best ≤ total` |
| `total` | число | число вопросов |
| `lastAt` | число | время последней проверки, мс |

### Черновик ответов (Draft) — `ielts.u.<userId>.drafts`
`{ [id текста]: { answers: { [id вопроса]: номер варианта }, checked: true|false } }`. Очищается «Пройти ещё раз».

### Экран (View) — `ielts.u.<userId>.view`
`{ screen: 'list'|'reading'|'vocab'|'cards', passageId }`.

### Сессия карточек (Cards) — `ielts.u.<userId>.cards`
`{ queue: [id слов, которые осталось показать], answered, known }` или `null`. Создаётся при входе на карточки, очищается «В словарь» на итоге. Слова, удалённые из словаря, выпадают при показе.

### Аккаунт (User) — `ielts.users`, сессия — `ielts.session`
- аккаунт: `{ id (UUID), email (строчными), salt, passwordHash, createdAt, legacyHandled }`;
- сессия: `{ userId, at }`; черновик email на экране входа — `ielts.authDraft`: `{ email }`.

### Временное состояние экранов (не сохраняется)
- в `Auth`: пароль, режим «Вход / Регистрация», ошибки, загрузка;
- в `Reading`: открытый попап `{ id, word, example, entry }`;
- в `Flashcards`: «перевёрнута».

## 3. Схема 1. Данные и связи

```
 СБОРКА (src/data/passages.json)          БРАУЗЕР (localStorage)            ПАМЯТЬ (App)
 ───────────────────────────────          ──────────────────────            ────────────

 ┌──────────────────────────┐             ┌──────────────────────────┐
 │ Текст                    │◄────────────┤ Слово  (ielts.vocab [ ]) │
 │  id ─────────────────────┼─ passageId ─┤  id, word, translation,  │
 │  title, topic,           │             │  example, status, addedAt│
 │  paragraphs              │             └────────────▲─────────────┘
 │                          │                          │ word совпадает
 │  words[ ] ───────────────┼──────────────────────────┘ без учёта регистра
 │   word, translation,     │    (подсвеченное слово → готовый перевод,
 │   example                │     сохранённое слово → зелёная подсветка)
 │                          │
 │                          │◄─ ключ ─────┬──────────────────────────┐
 │                          │             │ Результат (ielts.results)│
 │                          │             │  best, total, lastAt     │
 │                          │             └──────────────────────────┘
 │                          │
 │                          │◄─ ключ ─────────────────────────────── ┌───────────────────┐
 │  questions[ ]            │                                         │ Черновик (drafts) │
 │   id ◄───────────────────┼───── ключ в answers ───────────────────┤  answers, checked │
 │   options[4], answer     │                                         └───────────────────┘
 └──────────────────────────┘
```

Правила связей:
- `passageId` слова и ключи результатов и черновиков указывают на `id` текста. Проверки, что такой текст существует, нет.
- `id` вопросов (`q1`…`q5`) повторяются в разных текстах. Уникален только набор «текст + вопрос».
- Слово уникально по написанию во всём словаре, без привязки к тексту.

## 5. Где хранятся данные

| Данные | Где | Формат | Время жизни |
|---|---|---|---|
| Тексты, вопросы, ответы, подсвеченные слова | `src/data/passages.json` в JS-сборке | JSON | до новой сборки |
| Аккаунты, сессия, черновик email | `ielts.users`, `ielts.session`, `ielts.authDraft` | JSON | до «Выйти» (сессия) / успешного входа (email) |
| Словарь, результаты, ответы, экран, карточки | `ielts.u.<userId>.vocab`, `.results`, `.drafts`, `.view`, `.cards` | JSON | пока пользователь не очистит данные сайта |
| Данные до появления входа | `ielts.vocab`, `ielts.results` | JSON | до «Перенести» в окне переноса |

Чтение и запись (`src/storage.js`):
- **Чтение** — один раз при запуске: `JSON.parse`, затем `cleanVocab` или `cleanResults`. Повреждённые записи отбрасываются. Если словарь не массив или результаты не объект, используется пустое значение.
- **Запись** — после каждого изменения: значение целиком переписывается через `JSON.stringify`.
- **Ошибки** — ошибки `localStorage` (запрет, переполнение) глушатся. Значения живут в памяти вкладки (`memory` в `storage.js`) до перезагрузки, экран входа предупреждает об этом.

## 6. Ограничения текущей реализации

**Данные и пользователи**
- Вход — mock, сервера нет. «Аккаунты» и их данные живут в одном браузере и видны любому, у кого есть доступ к нему. У каждого адреса и порта своё хранилище (5173 и 4173 — разные).
- Две открытые вкладки не синхронизируются: событие `storage` не слушается, и при записи последняя вкладка перезапишет данные другой.
- Отброшенные повреждённые записи сразу исчезают из `localStorage`: очищенное значение тут же записывается. Восстановить их нельзя.
- Задержка «проверки» входа (0,5 с) искусственная — чтобы было видно состояние загрузки.

**Идентификаторы и связи**
- `id` слова собирается из слова и времени, его выдаёт браузер. Для базы данных такой `id` не подходит.
- Слово сохраняется строчными («London» → `london`) и уникально во всём словаре.
- `passageId` не сверяется с текстами. `passageId` и `lastAt` записываются, но нигде не показываются.

**Контент**
- Контент не проверяется при загрузке: структура держится на аккуратности файла.
- Правильные ответы лежат в сборке и видны в браузере.
- Подсвеченные слова совпадают только по точной форме слова, без учёта регистра.

**Код**
- Вся логика внутри компонентов. Счёт считается дважды: в `App.checkAnswers` и в `Reading`.
- Колода карточек фиксируется в начале сессии. «Не знаю» не возвращает слово в текущую сессию.
- Все операции синхронные. Нет состояний «загрузка» и «ошибка».
