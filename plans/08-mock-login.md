# План 08: обязательный mock-вход по email и паролю

**Статус:** согласован 2026-11-16 с предложенными вариантами: без `localStorage` вход и данные работают в памяти до перезагрузки с предупреждением; план 08, функция из раздела 9 — 09. **Выполнен 2026-11-16** (см. «Итог проверки» и «Отступления»).
**Дата:** 2026-11-16
**Изменён 2026-11-16 при обсуждении:** добавлено сохранение при перезагрузке (ответы, экран и текст, сессия карточек, email на экране входа).
**Основание:** PRD, раздел 5 — «Авторизация (mock, без обмена данными с внешними системами) — в итоговой версии ИДЗ1». Решения пользователя 2026-11-16:
- способ — email и пароль;
- вход обязательный;
- данные, сохранённые до входа, — окно «Перенести?»;
- на узком экране кнопка «Выйти» в шапке, логотип скрывается.

**Что такое mock.** Вход проверяет форму и переходы, но не подтверждает личность и не защищает данные. «Аккаунты» живут в `localStorage` этого браузера, внешних систем нет. Это честно пишется на экране входа.

Новых библиотек нет: `TextInput`, `PasswordInput`, `SegmentedControl`, `Modal` есть в `@mantine/core` 9.7.4. Хэш пароля считается встроенным в браузер Web Crypto (`crypto.subtle`, работает на `127.0.0.1`).

## Что меняется для пользователя
- При первом открытии — экран «Вход» вместо «Тексты». Без входа тексты и словарь недоступны.
- После входа всё работает как сейчас, у каждого аккаунта свои слова и результаты.
- Если в браузере есть слова и результаты, сохранённые до появления входа (сейчас у вас: 2 слова и результат 2/5 на 5173), после первого входа появится окно «Перенести в аккаунт?».
- В шапке появляется «Выйти». На узком экране надпись «IELTS Reading» скрывается.
- **При перезагрузке страницы ничего не слетает** (решение пользователя 2026-11-16): вход, словарь, результаты, ответы до «Проверить» и разбор, открытый экран и текст, сессия карточек, введённый на экране входа email. Подробно — в разделе «Сохранение при перезагрузке».

## Сохранение при перезагрузке
| Что | Сейчас | Станет | Когда очищается |
|---|---|---|---|
| Вход | — | сохраняется | «Выйти» |
| Словарь, результаты | сохраняются | сохраняются, отдельно для аккаунта | удаление слова / никогда |
| Ответы A–D и разбор | только в памяти | сохраняются по каждому тексту | «Пройти ещё раз» |
| Экран и открытый текст | всегда «Тексты» | открывается тот же экран (чтение нужного текста, словарь, карточки) | при переходе на другой экран |
| Сессия карточек | начинается заново | продолжается с той же карточки, счёт «знаю» сохраняется. Если уйти с карточек и вернуться — тоже продолжается | «В словарь» на итоге сессии; слова, удалённые из словаря, из колоды выпадают |
| Email на экране входа | — | остаётся в поле, пароль — никогда | успешный вход |

Не сохраняются: открытый попап слова, недописанный перевод в попапе, перевёрнута ли карточка (после перезагрузки она лицом вверх).

**Когда данные всё-таки пропадут** — это ограничения браузера, их нельзя обойти без сервера:
- пользователь очистил данные сайта или браузер их удалил;
- приватный режим: данные живут до закрытия окна;
- другой браузер, другое устройство или другой адрес (у 5173 и 4173 разные хранилища);
- браузер запрещает `localStorage` — тогда всё работает только до перезагрузки, и экран входа об этом предупреждает (решение 1).

## Экраны и тексты

**Экран «Вход»** (`src/screens/Auth.jsx`, новый)
- Шапка: только «IELTS Reading», без меню.
- Заголовок «Вход», переключатель «Вход | Регистрация».
- Поля «Email» и «Пароль» (с кнопкой «показать»).
- Под паролем на вкладке «Регистрация»: «Не меньше 8 символов».
- Кнопка: «Войти» или «Создать аккаунт» (чёрная, одна на экран).
- Подпись: «Демо-вход: личность не проверяется, данные не защищены и хранятся только в этом браузере. Не используйте настоящий пароль.»

**Окно «Перенести данные?»** (`Modal`)
- «В этом браузере есть слова (N) и результаты (M), сохранённые до входа. Перенести их в аккаунт?»
- Кнопки «Перенести» (чёрная) и «Не переносить» (белая).

**Шапка после входа:** `IELTS Reading | Тексты | Словарь | Выйти`. На узком экране `Тексты | Словарь | Выйти`.

## Состояния и переходы
```
 открыть приложение
   ├─ есть сохранённый вход ───────────────────────────────► Вошёл (экран «Тексты»)
   └─ нет ─► Экран «Вход» ─ кнопка ─► Проверка (~0,5 с, кнопка «загрузка», поля заблокированы)
                ▲                         ├─ верно ─► есть старые данные и аккаунт их ещё не видел?
                │                         │             ├─ да ─► окно «Перенести?» ─► Вошёл
                │                         │             └─ нет ──────────────────────► Вошёл
                │                         └─ ошибка ─► Ошибка над кнопкой, поля снова доступны, email сохранён
                └──────────────── «Выйти» (сразу, без подтверждения) ◄── Вошёл
```

| Состояние | Что видно |
|---|---|
| Не вошёл | Экран «Вход», вкладка «Вход» |
| Ошибка поля (после ухода из поля или нажатия кнопки) | «Введите email в формате name@example.com», «Пароль — не меньше 8 символов» |
| Проверка | Кнопка в состоянии загрузки, поля заблокированы |
| Ошибка входа | «Неверный email или пароль» |
| Ошибка регистрации | «Аккаунт с этим email уже есть. Войдите.» |
| Нет хранилища | «Браузер не разрешает сохранять данные: вход и слова сохранятся только до перезагрузки страницы.» Вход при этом работает в памяти |
| Вошёл | Как сейчас + «Выйти». После перезагрузки вход сохраняется |
| Выход | Экран «Вход». Данные аккаунта остаются в браузере |

## Данные (`localStorage`)
| Ключ | Что |
|---|---|
| `ielts.users` | `[{ id, email, salt, passwordHash, createdAt, legacyHandled }]`. `email` строчными, `id` — `crypto.randomUUID()`, хэш — SHA-256 от соли и пароля |
| `ielts.session` | `{ userId, at }` |
| `ielts.u.<userId>.vocab`, `ielts.u.<userId>.results` | словарь и результаты аккаунта, формат прежний, те же проверки `cleanVocab` / `cleanResults` |
| `ielts.u.<userId>.drafts` | `{ [passageId]: { answers: { [questionId]: 0–3 }, checked } }`; ответы на неизвестные тексты и вопросы отбрасываются |
| `ielts.u.<userId>.view` | `{ screen, passageId }`; неизвестный экран или текст → «Тексты» |
| `ielts.u.<userId>.cards` | `{ deck: [id слов], index, known }`; id, которых нет в словаре, отбрасываются, `index` и `known` ограничиваются размером колоды |
| `ielts.authDraft` | `{ email }` — только email, без пароля |
| `ielts.vocab`, `ielts.results` | старые данные без аккаунта, только для окна переноса |

Перенос: слова объединяются без дублей по написанию, у результатов берётся лучший `best`. После «Перенести» старые ключи удаляются. После «Не переносить» они остаются, а у аккаунта ставится `legacyHandled: true`, и окно ему больше не показывается.

## Решения на согласование
1. **Без хранилища.** Сейчас приложение работает без `localStorage` (PRD, раздел 6). При обязательном входе без хранилища оно стало бы недоступно.
   - **Предложение:** вход и данные работают в памяти до перезагрузки, с предупреждением на экране входа.
   - Альтернатива: без хранилища показывать только сообщение «Вход недоступен».
2. **Номер плана.** Этот план — 08, следующая функция из раздела 9 — 09.
